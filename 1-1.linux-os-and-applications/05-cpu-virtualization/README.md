## 강의 내용 정리

### 1. 시스템 가상화 (System Virtualization)
가상화는 물리적인 자원을 프로세스가 마치 독점하고 있는 것처럼 느끼게 만드는 추상화(Abstraction) 기법입니다.

#### 1.1 CPU 가상화
- 물리적인 CPU는 하나(또는 소수)지만, 다수의 프로세스가 동시에 실행되는 것처럼 보이게 만듭니다.
- 핵심 기법: 시분할(Time-sharing)을 통해 각 프로세스에 짧은 실행 시간(Time Slice)을 번갈아 할당합니다.

#### 1.2 메모리 가상화 (Memory Virtualization)
- OS는 각 프로세스에 독립적인 **가상 메모리(Virtual Memory)**를 제공합니다.
- 프로세스는 실제 물리 주소를 알 필요 없이 가상 주소만 바라보고 실행되며, 물리 메모리는 커널(OS) 영역과 사용자 영역으로 나뉘어 관리됩니다.
- OS의 역할: 가상 주소 ↔ 물리 주소 변환을 CPU(MMU)와 함께 수행.

### 2. 프로세스(Process)의 개념과 실행
프로세스는 디스크에 저장된 정적인 '프로그램'이 아니라, **실행 중인 프로그램(Active Entity)**을 의미합니다.

#### 2.1 프로세스의 메모리 구조 (4가지 세그먼트)
- **Code**: 컴파일된 바이너리 인스트럭션 저장.
- **Data**: 전역 변수·정적 변수 저장.
- **Heap**: 런타임에 크기가 결정되는 동적 메모리 할당 공간(유연하지만 접근이 상대적으로 느림).
- **Stack**: 지역 변수, 함수 호출 정보(리턴 주소), 파라미터 전달 등을 위한 공간. 재귀 호출이 깊어지면 계속 쌓이며, 힙 영역을 침범하거나 스택 오버플로우를 유발할 수 있습니다.

#### 2.2 프로세스 생성 과정
- 실행 파일을 디스크에서 메모리로 적재(Loading)하는 과정을 포함하며, 최근 프로그램은 크기가 커서 효율적인 로딩 방식이 중요해지고 있습니다.

### 3. 프로세스 상태 변화와 스케줄링
- **Ready(준비)**: CPU를 점유하기 위해 대기 중인 상태.
- **Running(실행)**: CPU를 점유하여 실제 인스트럭션을 수행 중인 상태.
- **Blocked(차단/대기)**: I/O 작업 등으로 CPU를 반납하고 기다리는 상태 — 이 사이 CPU는 다른 Ready 프로세스를 처리(병행 처리).
- **Terminated(종료)**: 태스크가 끝난 상태.

### 4. 프로세스 컨트롤 블록 (PCB)
- OS가 프로세스 관리를 위해 커널 자료구조에 저장하는 메타 정보 집합입니다 (PID, 프로세스 상태, PC, 레지스터 컨텍스트 등).
- **컨텍스트 스위칭**: 실행 중인 프로세스를 교체할 때, 현재 CPU 레지스터 값을 PCB에 저장하고 다음 프로세스의 저장된 정보를 복구하여 실행을 이어갑니다.

### 5. 산업 및 기술 트렌드 (참고)
- **CXL(Compute Express Link)을 통한 메모리 확장**: H200과 같은 고성능 GPU/서버 환경에서 메모리 용량·대역폭 한계를 보완하기 위해, CXL 기반 메모리 확장 장치를 개발하는 팹리스·메모리 업체들의 움직임이 활발합니다.
- **파이프라인 버블(Pipeline Bubble)**: 명령어 파이프라인에서 연산이 비어있는 구간(버블)을 줄이기 위한 컴파일러·런타임 차원의 최적화 연구.
- **Prefill/Decode 분리 (P/D Disaggregation)**: 최근 LLM 서빙 최적화 기법 중 하나로, 연산 특성이 다른 Prefill 단계와 Decode 단계를 서로 다른 GPU(또는 GPU 풀)에 분리 배치해 자원 활용률을 높이는 방식입니다.

### 복습 포인트
- 같은 코드에서 찍은 포인터(p)의 주소값이 프로세스마다 동일하게 나올 수 있는 이유 → OS가 메모리 가상화를 통해 각 프로세스에게 독립적인 가상 주소 체계를 보여주기 때문.
- I/O 요청 시 프로세스 상태가 Running → Blocked로 변하는 이유 → I/O는 CPU 처리 속도보다 훨씬 느리므로, 그동안 CPU가 다른 작업을 처리할 수 있도록 스케줄링하기 위함.
