## 강의 내용 정리

### 1. 메모리 가상화의 진화 과정
다중 프로그래밍(Multi-programming)과 자원의 효율적 공유를 달성하기 위해 운영체제가 메모리를 관리해온 흐름을 시간 순으로 정리합니다.

#### 1.1 시분할 (Time Sharing) 기법
- **개념**: 오직 하나의 프로세스만 물리 메모리에 통째로 적재하여 실행합니다. 할당된 CPU 시간(Time Slice)이 지나면 현재 프로세스의 메모리 내용을 디스크 스왑 영역으로 내려보내고(Swap-out), 다음에 실행할 프로세스의 데이터를 메모리로 올려(Swap-in) 실행합니다.
- **한계**: 공간적 공유가 전혀 없어 단 하나의 프로세스만 메모리에 상주하며, 프로세스 전환 시마다 거대한 메모리 데이터를 디스크와 주고받아야 해 전환 비용이 매우 큽니다.

#### 1.2 정적 재배치 (Static Relocation)
- **개념**: 여러 프로그램을 메모리의 서로 다른 영역에 동시에 적재(Space Sharing)합니다. 컴파일 또는 로드 시점에 프로그램의 주소를 물리 메모리 주소에 맞춰 변환·고정합니다.
- **한계**: 주소가 고정되어 있고 하드웨어적인 접근 제어가 없어, 프로세스가 오작동하거나 악의적으로 동작할 경우 다른 프로세스나 OS의 메모리 영역을 침범할 수 있는 보안 취약점이 발생합니다.

#### 1.3 동적 재배치 (Dynamic Relocation)와 MMU
- **개념**: 프로세스가 실제로 실행되는 시점(런타임)에 주소를 동적으로 변환합니다. 컴파일러는 물리 주소를 몰라도 되며, 모두 0번지부터 시작하는 가상 주소(Virtual Address) 공간을 가정하고 코드를 생성합니다.
- **MMU (Memory Management Unit)**: 가상 주소를 물리 주소로 실시간 변환하는 전용 하드웨어입니다. 과거에는 별도의 칩으로 존재하기도 했지만, 현대 아키텍처에서는 대부분 CPU 내부에 내장되어 있습니다.
- **베이스/바운드 레지스터**: 베이스(프로세스가 적재된 물리 메모리의 시작 주소)와 바운드(가상 메모리의 크기 한계)를 이용해 `물리 주소 = 가상 주소 + 베이스` 공식으로 변환합니다. 가상 주소가 바운드를 초과하면 Segmentation Fault를 발생시켜 프로세스를 강제 종료함으로써 다른 프로세스의 메모리를 보호합니다.

### 2. 하드웨어 아키텍처와 메모리 관리 고도화
#### 2.1 세그멘테이션 (Segmentation) 기법
- **개념**: 가상 메모리 공간을 Code, Heap, Stack 등 논리적 단위인 세그먼트(Segment)로 나누어 관리합니다. 각 세그먼트는 개별적인 베이스/바운드 쌍을 가집니다.
- **세그먼트 테이블**: MMU 내부에서 가상 주소의 상위 비트(Segment 식별 비트)로 어느 세그먼트에 속하는지 판별합니다.
- **한계**
  - **외부 단편화(External Fragmentation)**: 크기가 제각각인 세그먼트들이 할당·해제를 반복하면서, 어느 세그먼트도 들어갈 수 없는 자투리 빈 공간들이 메모리 곳곳에 쌓입니다.
  - **테이블 크기 딜레마**: 단편화를 줄이려고 세그먼트를 잘게 나눌수록 세그먼트 테이블 자체의 크기가 커져, 한정된 MMU 하드웨어 공간에 다 담을 수 없게 됩니다.

#### 2.2 페이징(Paging) 기법의 도입과 하이브리드 전략
- **개념**: 외부 단편화를 근본적으로 없애기 위해, 가상/물리 메모리를 논리적 단위가 아닌 고정된 크기(Page/Page Frame)로 균등하게 나눕니다. 크기가 고정되어 있으므로 외부 단편화가 발생하지 않습니다.
- **성능 보완**: 페이지 단위가 많아지면 페이지 테이블 자체도 커지므로 메인 메모리(DRAM)에 두되, 자주 참조되는 페이지 변환 엔트리만 하드웨어 캐시인 **TLB(Translation Lookaside Buffer)**에 담아 속도와 대용량이라는 두 이점을 함께 취합니다.

#### 2.3 하드웨어/소프트웨어 최적화 관점
- 하드웨어(MMU/TLB)는 정형화되고 반복적인 주소 변환을 빠르게 처리하는 역할을 맡고, 복잡한 정책 결정과 자료구조 관리는 오버헤드가 상대적으로 적은 소프트웨어(OS 커널)가 담당하는 역할 분담이 일반적입니다.

### 3. 운영체제 보안과 실행 단위
- **멀티스레딩 동기화 책임**: 스레드들이 프로세스의 공유 메모리 공간(Heap 등)에 동시 접근할 때 발생하는 데이터 일관성 문제는 CPU나 OS가 자동으로 해결해주지 않으며, **응용 프로그램 개발자가 락 등으로 직접 설계·구현해야 할 책임**입니다.
- **커널 모드(Kernel Mode)의 위험성**: 커널 모드로 동작하는 코드는 시스템 전체의 물리 레지스터·메모리에 사실상 제한 없이 접근할 수 있습니다. 악성 코드가 취약점을 통해 커널 권한을 획득하면 시스템 전체의 보안이 무너질 수 있으므로, 이런 최악의 시나리오를 가정하고 방어 대책을 세우는 것을 **위협 모델(Threat Model)**이라고 부릅니다.

### 4. 향후 방향: AI 시대의 시스템 소프트웨어
> 아래 내용은 강의에서 제시된 향후 전망이며, "AI OS"는 업계에서 통일된 정의가 있는 표준 용어라기보다는 강의에서 제안하는 방향성에 가깝습니다.

- 기존 운영체제는 범용 연산기인 CPU 중심의 자원 할당·관리에 최적화되어 발전해 왔습니다.
- 강의에서는 GPU 클러스터, NPU, 초고속 서버 네트워크 등 대규모 인프라 위에서 분산 학습·추론·대규모 배치(Batch) 작업을 효율적으로 수행하도록 하위 하드웨어를 추상화하고, 상위 딥러닝 프레임워크들을 유기적으로 제어하는 차세대 리소스 관리 계층을 "AI OS"라는 방향성으로 소개합니다.
- 현재 LLM 서빙이나 GPU 학습/추론 워크로드는 대부분 트랜스포머 아키텍처 기반이라 연산·메모리 접근 패턴이 비교적 정형화되어 있지만, 응용 프로그램의 요구사항이 빠르게 변화하고 있어 이에 유연하게 대응할 수 있는 아키텍처 설계 능력이 중요해지고 있습니다.

### 향후 계획 (강의 노트 기준)
1. 단편화를 방지하는 다단계 페이징(Multi-level Paging) 및 가상 메모리 관리 기법 심화 학습.
2. AI OS 관련 교과목 학습 계획: CPU/GPU 아키텍처 상호작용, 분산 환경에서의 메모리·IO 병목 해결 방안.
3. AI 시대 대응을 위한 커널 수준 리소스 스케줄링·가상화 레이어 연구.
