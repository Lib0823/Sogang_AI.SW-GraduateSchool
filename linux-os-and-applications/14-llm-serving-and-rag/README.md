## 강의 내용 정리

### 1. 생성형 AI의 기본 구조 - 트랜스포머(Transformer)
- 2017년 논문 "Attention Is All You Need"에서 제안된 딥러닝 구조로, 현재 대부분의 생성형 AI 모델의 기반이 됩니다.
- 기존 RNN 기반 모델은 문장이 길어질수록 앞부분 정보를 잊어버리는 경향이 있었지만, 트랜스포머는 **Attention** 메커니즘으로 문장 전체의 문맥(Context)을 한 번에 고려할 수 있습니다.
- 특징: 문장 전체를 동시에 처리, 장기 의존성(Long-Term Dependency) 문제 완화, 병렬 처리 가능, 번역·요약·질의응답 등 다양한 생성 작업에 활용.

### 2. 임베딩(Embedding)
- AI 모델은 텍스트를 직접 이해하지 못하므로 숫자 벡터(Vector)로 변환합니다 (예: "생성형 AI" → [0.15, 0.72, 0.34, ...]).
- **임베딩 차원**: 벡터의 길이를 의미합니다 (예: 768, 1024, 4096차원). 차원이 클수록 더 많은 의미 정보를 표현할 수 있지만, 계산량과 메모리 사용량도 함께 증가합니다.

### 3. Attention 메커니즘
트랜스포머의 핵심 기술로, Query·Key·Value(QKV) 구조를 사용합니다.
- **Query(Q)**: 찾고 싶은 정보 / **Key(K)**: 각 데이터가 가진 정보의 특징 / **Value(V)**: 실제로 참조할 정보.
- Q와 K의 유사도를 계산해, 그 유사도에 따라 V들을 가중합하여 결과를 만듭니다.
- **수식**: `Attention(Q,K,V) = Softmax(QKᵀ / √dk)V`
- **계산 과정**: Q·K의 유사도(내적) 계산 → 값이 너무 커지지 않도록 √dk로 나누어 스케일링 → Softmax로 가중치화 → V와 곱해 최종 결과 생성.
- **Multi-Head Attention**: 하나의 Attention을 여러 '헤드'로 나누어 병렬로 수행하는 방식으로, 서로 다른 관점(문법적 관계, 의미적 관계 등)의 정보를 동시에 포착해 문맥 이해 능력을 높입니다.

### 4. 인코더(Encoder)와 디코더(Decoder)
- **인코더**: 입력 문장을 읽어 문맥 정보가 담긴 벡터 표현을 생성합니다.
- **디코더**: 인코더의 출력(또는 지금까지 생성한 토큰들)을 바탕으로 다음 토큰을 순차적으로 생성합니다.
- **현재 LLM 구조**: GPT, ChatGPT, Llama 등 최근의 대표적인 생성형 언어모델은 인코더 없이 **디코더만으로 구성된 Decoder-Only** 구조를 사용하며, 텍스트 생성 작업에 최적화되어 있습니다.

### 5. LLM 추론(Inference) 과정
- **Prefill 단계**: 사용자 입력 전체를 한 번에 읽고 처리하는 단계입니다 (토큰화 → 임베딩 → QKV 계산 → KV Cache 생성). 첫 번째 출력 토큰을 생성하기 직전까지의 과정에 해당합니다.
- **Decode 단계**: 토큰을 한 번에 하나씩 생성하는 단계입니다. 이전에 생성된 토큰과 KV Cache를 재사용하며 다음 토큰 생성을 반복합니다.

### 6. KV Cache
- 디코딩 과정에서 매 토큰마다 이전 토큰들의 Key·Value를 처음부터 다시 계산하면 매우 비효율적이므로, 한 번 계산한 Key·Value를 저장해두고 재사용합니다. 이를 KV Cache라고 합니다.
- **장점**: 연산량 감소, 응답 속도 향상, GPU 활용 효율 증가.
- **문제점**: 생성되는 토큰 수가 늘어날수록 KV Cache도 함께 증가해 GPU 메모리 사용량이 커집니다. 모델과 입력 길이에 따라서는 KV Cache가 모델 가중치(Weight)보다 더 많은 메모리를 차지하는 경우도 있습니다.

### 7. 생성형 AI의 메모리 문제
- 입력·출력 길이가 길어질수록 KV Cache가 계속 증가해, 극단적인 경우 GPU 메모리 부족(**Out Of Memory, OOM**)이 발생할 수 있습니다.

### 8. 메모리 최적화 기술
| 기법 | 설명 | 장점 | 단점 |
|------|------|------|------|
| Quantization | 가중치·활성값의 숫자 표현 비트를 줄임 (FP16 2Byte, INT8 1Byte, INT4 0.5Byte) | 메모리 사용량 감소, 연산 속도 향상 | 정확도 저하 가능 |
| Compression | 중요한 정보만 남기고 KV Cache 등을 압축 | 저장 공간·메모리 사용량 감소 | 과도한 압축 시 정확도 저하 |
| Token Pruning | 상대적으로 덜 중요한 토큰(의 KV) 제거 | 계산량·메모리 감소 | 문맥 손실 가능 |

### 9. 시스템 관점의 AI 운영
- 모델을 연구하는 입장에서는 정확도와 성능 향상을 중시하지만, 서비스를 운영하는 입장에서는 Throughput(처리량), Latency(지연 시간), 비용, 메모리 사용량을 함께 고려해야 합니다. 따라서 **정확도가 높은 모델과 실제 서비스에 적합한 시스템은 반드시 같은 방향을 가리키지 않습니다.**

### 10. Paged Attention
- 운영체제의 페이징(Paging) 개념을 KV Cache 관리에 적용한 기법으로, KV Cache를 고정 크기 블록 단위로 관리해 메모리 단편화를 줄이고, 여러 요청 간 메모리를 유연하게 공유할 수 있게 합니다. 이를 통해 메모리를 더 효율적으로 사용하며 대규모 동시 요청을 처리할 수 있습니다. LLM 서빙 엔진 **vLLM**이 이 기법을 도입한 것으로 잘 알려져 있습니다.

### 11. 성능 평가 지표
- **Throughput**: 단위 시간당 처리량 (예: 1000 Tokens/sec).
- **Latency**: 요청 후 응답까지 걸리는 시간 (예: 첫 토큰 생성까지 200ms, 이를 TTFT라고도 부릅니다).
- **SLA(Service Level Agreement)**: 서비스가 지켜야 할 품질 목표 (예: 요청의 95%를 1초 이내에 처리).

### 12. RAG (Retrieval-Augmented Generation)
- 모델이 학습 시점에 알지 못했던 정보를 외부 문서에서 검색해 답변에 반영하는 기법입니다: 질문 → 관련 문서 검색 → 검색된 문서를 프롬프트에 첨부 → LLM이 이를 바탕으로 응답 생성.
- **장점**: 모델을 재학습하지 않고도 최신 정보나 도메인 지식을 활용할 수 있습니다.
- **단점**: 문서 검색 과정이 추가되어 Prefill 단계(입력 처리 시간)가 길어질 수 있습니다.

### 13. Agent AI 시대
- 기존 AI가 질문에 바로 답변을 생성했다면(질문 → 답변), Agent AI는 질문을 받아 스스로 계획을 세우고 DB 조회, API 호출, 파일 처리 등의 중간 단계를 거쳐 결과를 만들어냅니다(질문 → 계획 수립 → 도구 호출 → 결과 생성). 여러 Agent가 서로 협업하는 구조도 가능하며, 그만큼 시스템 자원 사용량도 늘어납니다.

### 14. Agent AI 시대에 CPU가 중요한 이유
- Agent가 늘어나면 이를 처리하는 프로세스와 스레드 수가 함께 늘어나고, 그만큼 CPU의 스케줄링 부담도 커집니다. CPU는 프로세스 관리, 스레드 스케줄링, 네트워크 처리, DB 연결 관리, Agent 실행 등을 담당하므로, Agent AI 시대에는 **GPU 성능뿐 아니라 CPU 성능도 서비스 전체 성능에 중요한 영향을 미칩니다.**

### 시험 대비 핵심 요약
1. 트랜스포머의 핵심 기술은 Attention이다.
2. Attention은 Query(Q), Key(K), Value(V) 구조를 사용한다.
3. GPT 계열은 Decoder-Only 구조를 사용한다.
4. 추론 과정은 Prefill → Decode 순서로 진행된다.
5. KV Cache는 이전에 계산한 Key·Value를 저장해 재계산을 줄이고 속도를 높인다.
6. LLM 서비스의 주요 메모리 문제는 KV Cache 증가에 따른 GPU 메모리 부담이다.
7. 메모리 최적화 방법에는 Quantization, Compression, Token Pruning 등이 있다.
8. Paged Attention은 OS의 페이징 개념을 응용해 KV Cache를 효율적으로 관리하는 기술이다.
9. RAG는 외부 지식을 검색해 답변 생성에 활용하는 기법이다.
10. Agent AI 시대에는 GPU뿐 아니라 CPU의 중요성도 함께 커진다.
