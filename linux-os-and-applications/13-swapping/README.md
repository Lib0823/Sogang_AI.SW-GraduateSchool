## 강의 내용 정리

### 1. 프로세스와 프로세스 제어 블록 (PCB) 개념
- **프로세스**: 실행 중인 프로그램의 인스턴스로, 기본적으로 하나의 실행 흐름(Thread)을 포함하며 부모-자식 관계의 계층 구조를 가집니다.
- **PCB**: 커널이 프로세스를 관리하기 위해 사용하는 자료구조로, 프로세스의 컨텍스트(Context)를 담습니다. CPU 레지스터 값(EIP, ESP 등)이 특정 시점의 프로세스 상태를 결정합니다.

### 2. 리눅스의 프로세스 관리
- **task_struct**: 리눅스 커널에서 PCB 역할을 하는 구조체.
- **Task List**: 모든 task_struct는 이중 연결 리스트(Doubly Linked List)로 관리됩니다.
- **상태 관리**: 프로세스는 Ready, Running, Blocked 등의 상태를 오가며 스케줄링됩니다.
- **xv6**: MIT의 교육용 유닉스 계열 OS로, 리눅스와 유사한 구조를 가지면서도 코드가 단순해 핵심 메커니즘을 이해하는 데 적합합니다.

### 3. 레지스터와 CPU 실행 모델
- **범용 레지스터**: EAX, EBX, ECX, EDX 등(x86 32비트 기준). 이름에 특정 용도가 붙어 있어도, 컴파일러 최적화에 따라 실제로는 다양한 값을 담는 범용 저장 공간처럼 쓰입니다 (예: ECX는 이름은 'Counter'이지만 반복문 카운터 외의 용도로도 흔히 사용됨).
- **특수 목적 레지스터**: EIP(Instruction Pointer, 다음 실행할 명령어의 주소), ESP(Stack Pointer, 현재 스택의 최상단 주소).

### 4. 메모리 관리: 가상 메모리와 매핑
- **가상 메모리**: 프로그래머는 물리 주소를 몰라도 0번지부터 시작하는 연속된 선형 주소 공간을 사용한다고 가정합니다. 커널 공간과 사용자 프로세스 공간을 분리해 시스템을 보호합니다.
- **매핑 테이블**: 가상 주소를 물리 주소로 변환하는 역할을 합니다.
  - **리니어 매핑**: 가장 단순한 방식이지만, 메모리 단편화가 발생하면 연속된 공간을 확보하지 못해 프로세스를 할당하지 못하는 문제가 생깁니다.
  - **스캐터 매핑**: 파편화된 공간을 효율적으로 사용하기 위해, 물리 메모리 곳곳에 흩어진 프레임들을 하나의 연속된 가상 주소 공간으로 연결하는 매핑 테이블을 사용합니다.

### 5. 멀티스레딩과 병행성 (Concurrency)
- **스레드**: 프로세스 내의 실행 흐름 하나. 여러 스레드가 하나의 프로세스 자원(메모리, 변수 등)을 공유해 메모리 효율이 높고 병렬 처리가 가능해집니다.
- **원자성(Atomicity) 문제**: 동기화 문제는 여러 스레드가 공유 변수(카운터 등)를 동시에 수정할 때 발생합니다. Load → Update → Store 세 과정이 원자적으로 실행되지 않기 때문입니다 (예: 두 스레드가 거의 동시에 같은 값 10을 읽어와 각각 11로 갱신·저장하면, 실제로는 2가 늘어나야 하지만 1만 반영되는 현상이 나타남). 정확한 동기화 기법을 적용해야만 해결할 수 있습니다.

### 복습 포인트
- PCB와 컨텍스트 스위칭: CPU 레지스터 상태가 왜 프로세스의 '현재 상태'가 되는지 이해하기.
- 스케줄링 단위: 현대 OS는 프로세스가 아닌 스레드 단위로 스케줄링을 수행한다는 점.
- 동기화의 책임: 병행 프로그래밍에서 발생하는 문제는 개발자의 책임이 크며, 정확한 동기화 기법(Atomic 연산, Lock 등)이 필요합니다.
