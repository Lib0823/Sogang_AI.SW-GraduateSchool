## 강의 내용 정리

### 1. 컴퓨터 구조를 바라보는 관점의 전환
- 전자공학적 신호 처리부터 시작하는 상향식 학습보다, 현재 구동 중인 시스템(OS, 애플리케이션)이 왜 이 자원을 필요로 하는지 거꾸로 올라가는 역추적 방식이 개념을 잡는 데 더 효율적이라는 관점을 제시.
- CPU와 메모리는 독립된 개체가 아니라 강하게 결합(Coupled)된 관계이며, 최신 아키텍처일수록 두 요소가 하나의 구조체처럼 긴밀하게 동작하는 경향이 강해지고 있음.

### 2. 메모리 계층 구조와 캐시
- **메모리 종류**
  - LPDDR: 저전력이 중요한 모바일·임베디드 환경에서 주로 사용되는 DDR 계열 메모리.
  - HBM(High Bandwidth Memory): 여러 층의 DRAM 다이를 수직으로 적층해 좁은 면적에서 대역폭을 극대화한 메모리로, GPU·AI 가속기의 필수 구성 요소.
  - DRAM: 데이터를 유지하기 위해 주기적으로 리프레시(Refresh) 동작이 필요하며, 이 과정에서 전력 소모와 발열이 발생.
- **캐시 계층**: L1/L2는 코어별 전용(Private) 캐시, L3는 여러 코어가 공유(Shared)하는 캐시.
- **SRAM**: 레지스터와 캐시에 사용되는 소자로, 리프레시가 필요 없고 DRAM보다 훨씬 빠르지만 셀 구조가 복잡해 단가와 면적 비용이 높음.
- **캐시 블록(Cache Line)**: 메인 메모리와 캐시가 데이터를 주고받는 최소 단위로, 보통 64바이트입니다.
- **교체 알고리즘(Replacement Policy)**: 캐시 공간이 부족할 때 어떤 데이터를 내보낼지 결정하는 정책 (예: LRU).
- **Write Policy**
  - Write-Through: 캐시와 메모리를 동시에 갱신 — 일관성은 확실하지만 매 쓰기마다 메모리 접근이 필요해 느림.
  - Write-Back: 캐시에만 먼저 쓰고, 해당 캐시 라인이 축출(evict)될 때 메모리에 반영 — 쓰기 속도가 빠르며, CPU는 항상 최신 데이터가 있는 캐시를 먼저 조회하므로 프로그램 실행 관점에서는 데이터 불일치 문제가 발생하지 않음.
  - Write Allocate: 쓰기 대상 데이터가 캐시에 없을 경우, 먼저 메모리에서 캐시로 로드한 뒤 갱신하는 방식.

### 3. NVIDIA와 현대 하드웨어 통합 트렌드
- NVIDIA는 그래픽 카드 제조사를 넘어 GPU 간 연결(Interconnect)과 데이터센터 전체를 설계하는 기업으로 자리잡았으며, 그 핵심 기술 중 하나가 GPU 간 초고속 통로인 **NVLink**입니다.
- 과거 메인보드에 별도 칩으로 분리되어 있던 노스브릿지(메모리·그래픽 제어), 사우스브릿지(I/O 제어) 기능은, 현대 CPU와 모바일 SoC에서는 점차 다이(die) 내부로 통합되는 추세이며, 이를 통해 데이터 이동 경로가 짧아지고 처리 속도가 개선됩니다.

### 4. CPU 연산과 데이터 핸들링
- **메모리 리드 트랜잭션**: 연산을 위해 메모리에서 레지스터로 데이터를 가져오는 과정.
- **Word Size**: 레지스터는 보통 8바이트(64비트) 단위로 데이터를 읽으며, 1바이트짜리 데이터를 읽더라도 하드웨어 수준에서는 8바이트 단위로 함께 처리하는 구조를 가짐.
- **인터럽트(Interrupt)**: 예상치 못한 예외 상황이나 외부 이벤트가 발생했을 때 CPU가 현재 작업을 멈추고 대응하는 메커니즘.

### 5. 스토리지 인터페이스의 진화: SATA에서 NVMe까지
- **SATA (2003년 등장)**: 초기 SATA는 HDD의 물리적 회전 속도에 맞춰 설계되었으며, 이후 SSD가 등장해 병렬 데이터 처리가 가능해지자 SATA III(약 6Gbps, 실효 약 600MB/s) 대역폭이 병목이 되었습니다.
- **NVMe**: SSD의 고속 성능을 온전히 활용하기 위해, 저장장치 전용 통로 대신 그래픽카드가 사용하는 PCIe 인터페이스를 그대로 활용하는 방식입니다.
- **전송 인코딩**: 구형 인터페이스(SATA, 초기 PCIe)는 오류 검출을 위해 8비트 데이터를 10비트로 변환해 전송하는 8b/10b 인코딩을 사용해 약 20%의 오버헤드가 있었지만, PCIe 3.0부터는 128b/130b 인코딩으로 오버헤드가 약 1.5% 수준으로 크게 줄었습니다.

### CPU/GPU 물리 구조 (병행 자료)
- **SoC (System on Chip)**: 코어, 캐시 등 여러 구성 요소가 하나의 칩에 통합된 형태.
- **멀티 코어 / 멀티 프로세서**: 코어 수가 늘어날수록 병렬 처리 능력이 커지며, 서버급 시스템에서는 여러 개의 CPU 소켓을 사용하기도 함.
- **PATA → SATA**: PATA(병렬 방식)는 여러 신호선으로 동시에 데이터를 보내지만, 수신 측에서 각 신호를 순서대로 다시 맞추는 과정에서 오버헤드가 발생합니다. SATA(직렬 방식)는 하나의 고속 채널로 순서대로 전송함으로써 오히려 이 오버헤드를 줄여 더 높은 실효 성능을 낼 수 있었고, 이후 SATA가 PATA를 대체하게 되었습니다.
- **캐시 3단계 (L1/L2/L3)**: L1은 '개인 책상 위'처럼 가장 빠르고 작은 공간, L2는 '책꽂이', L3는 여러 코어가 함께 쓰는 '공용 서가'에 비유할 수 있습니다. 모든 단계에서 데이터를 찾지 못하면 결국 DRAM(메인 메모리)까지 접근해야 합니다.
- **Register → SRAM → DRAM 접근 순서**: CPU는 이 순서로 데이터를 탐색하며, SRAM과 DRAM 간 통신은 Cache Line 단위(대개 64바이트)로 이루어집니다.
