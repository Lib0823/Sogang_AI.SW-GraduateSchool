## 강의 내용 정리

### 1. CPU와 어셈블리 언어
- 어셈블리 언어는 기계어와 거의 1:1로 대응되는 저급 언어로, 레지스터(eax 등)를 프로그래머가 직접 제어할 수 있습니다.
- **명령어 실행 주기**: CPU는 Fetch(인출) → Decode(해석) → Execute(실행)의 순서를 반복하며 명령어를 처리합니다.
- **프로그램 카운터(PC)**: 다음에 실행할 명령어의 주소를 가리키며, 하나의 명령어를 가져올 때마다 자동으로 값이 갱신됩니다(x86-64에서는 명령어 길이에 따라 갱신 폭이 달라짐).

### 2. 메모리 계층 구조와 캐시 (복습)
- 계층 구조: 위로 갈수록 빠르고 비싸며 용량은 작아집니다 (Register > L1 > L2 > L3 > DRAM > HDD/SSD).
- 캐시의 목적: 상대적으로 느린 메인 메모리(DRAM) 접근 횟수를 줄여 CPU 성능을 끌어올리는 것이며, SRAM 소자를 사용합니다.
- L1/L2는 코어별 전용(Private) 캐시, L3는 여러 코어가 함께 사용하는 공유(Shared) 캐시입니다.
- 캐시 블록: 메인 메모리와 캐시가 데이터를 주고받는 최소 단위(보통 64바이트)입니다.

### 3. 캐시 관리 알고리즘 및 정책
- 교체 알고리즘: 캐시 공간이 부족할 때 어떤 데이터를 내보낼지 결정합니다 (예: LRU).
- **Write-Through** (캐시·메모리 동시 갱신, 느리지만 항상 일관됨) / **Write-Back** (캐시에 먼저 기록 후 축출 시 메모리에 반영, 빠름) / **Write Allocate** (쓰기 대상이 캐시에 없으면 먼저 로드 후 갱신).

### 4. CPU의 물리적 구조
- SoC(System on Chip): 코어·캐시 등이 하나의 칩에 통합된 형태.
- 멀티 코어 / 멀티 프로세서: 코어 수가 늘어날수록 병렬 처리 능력이 커지며, 서버급 시스템에서는 여러 개의 CPU 소켓을 사용하기도 함.

### 5. 운영체제(OS)의 역할과 시스템 콜
- **핵심 역할**: 자원 관리의 효율성(Efficiency)과 시스템의 올바른 동작(Correctness)을 보장하는 것.
- **추상화**: 하드웨어를 프로그래머가 다루기 쉬운 형태로 추상화하여, 메모리 적재나 장치 제어 같은 복잡한 하드웨어 조작을 직접 하지 않아도 되게 함.
- **시스템 콜(System Call)**: 사용자 프로그램이 커널이 제공하는 기능을 요청하기 위한 인터페이스로, 프로세스 생성이나 파일 접근 등은 모두 시스템 콜을 통해 이루어집니다.

### 복습 팁
"Write-Back 정책에서 캐시와 메모리 값이 서로 다른 상태로 남아 있는데도 프로그램이 왜 문제없이 동작하는가?"를 다시 정리해 볼 것. 메모리에는 아직 예전 값이 남아 있더라도, CPU는 항상 최신 데이터를 가진 캐시를 먼저 조회하도록 설계되어 있기 때문에 프로그램 실행 관점에서는 데이터 일관성이 유지된다는 점이 핵심입니다.
