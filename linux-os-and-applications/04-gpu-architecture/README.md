## 강의 내용 정리

이번 주차는 정규 슬라이드 대신 GPU 아키텍처에 대한 보충자료를 중심으로 진행되었습니다.

### 1. GPU 아키텍처 핵심 구성요소
- **CUDA Core**: GPU의 가장 기본적인 연산 단위로, FP32/FP64 부동소수점이나 INT32 정수 연산을 수행합니다. 수천 개의 코어가 동시에 작동해 병렬 연산 속도를 높입니다.
- **Warp Scheduler**: 32개의 스레드 묶음인 'Warp' 단위로 실행을 관리·지시하는 역할을 합니다. 매 클록마다 실행 준비가 된 워프를 선택해 연산 유닛에 할당함으로써, 메모리 접근으로 대기 중인 워프 대신 다른 워프를 실행해 전체 가동률을 높입니다.
- **Register File**: 각 스레드가 연산 중 사용하는 가장 빠른 전용 저장 공간입니다. GPU는 레지스터 파일이 매우 크고 많아, 스레드 전환 시 데이터를 메모리로 옮길 필요 없이 즉시 다른 스레드의 작업을 이어갈 수 있습니다.
- **Shared Memory (L1 캐시 겸용)**: 같은 SM(Streaming Multiprocessor) 내 스레드들이 데이터를 공유할 수 있는 온칩(On-chip) 메모리로, 프로그래머가 직접 제어할 수 있는 캐시 역할을 하며 외부 Global Memory 접근을 줄여줍니다.

### 2. CPU vs GPU 설계 철학
- **CPU (Sequential Control)**: 싱글 스레드 성능 극대화에 초점을 둡니다. 조건문(If), 분기(Jump), 시스템 콜 처리 같은 복잡하고 예측이 어려운 연산을 위해 큰 제어 유닛과 캐시를 갖춥니다.
- **GPU (Parallel Throughput)**: 수천 개의 스레드를 동시에 실행하는 병렬 처리에 특화되어 있습니다. 32개의 스레드를 하나의 Warp로 묶어 동일한 명령어에 서로 다른 데이터를 투입하는 **SIMT(Single Instruction, Multiple Threads)** 방식을 사용합니다.
- **ALU/레지스터 규모**: CPU는 소수의 고성능 ALU를 갖는 반면, GPU는 수만 개의 단순한 연산 유닛(CUDA 코어)을 가집니다. 예를 들어 NVIDIA Fermi 아키텍처의 SM(Streaming Multiprocessor)은 32비트 레지스터 32,768개(128KB)로 구성된 대규모 레지스터 파일을 갖추어, 다수의 스레드 컨텍스트를 동시에 유지할 수 있습니다.

### 3. 스트리밍 멀티프로세서(SM)와 메모리 계층
- SM은 명령어 캐시, Warp Scheduler, 디스패치 유닛을 갖춘 독립적인 연산 엔진입니다.
- HBM(High Bandwidth Memory) 접근에는 수백 사이클 수준의 긴 지연 시간이 소요되는데, 이를 극복하기 위해 다수의 Warp Scheduler를 두어 한 워프가 메모리 로딩을 기다리는 동안 다른 워프를 실행함으로써 지연 시간을 감추는 방식(Latency Hiding)을 사용합니다.
- 최근의 대규모 AI 모델은 GPU 한 장의 메모리 용량을 초과하는 경우가 많아 여러 GPU에 나누어 배치하게 되며, 이때 GPU 간 통신(P2P Communication)이 성능의 병목이 되기 쉽습니다.

### 4. OS의 역할과 리소스 가상화 (연결 개념)
- OS는 리소스 매니저로서 디바이스 드라이버(하드웨어 종속 소프트웨어)와 커널(시스템 콜·파일시스템·프로세스/메모리 관리)을 통해 하드웨어를 추상화합니다.
- 메모리 가상화: 프로그래머가 다루는 주소는 가상 주소이며, 각 프로세스는 독립된 가상 주소 공간을 가져 서로 다른 프로세스의 데이터가 섞이지 않도록 보호됩니다.

### 5. 프로세스와 하이퍼스레딩
- 프로세스는 실행 파일이 메모리에 적재되면 OS가 고유한 PID를 부여해 관리하는 실행 단위입니다.
- **하이퍼스레딩(Hyper-Threading)**: 하나의 물리 코어에 두 개의 실행 흐름(파이프라인)을 두어, 소프트웨어 관점에서는 코어가 두 개인 것처럼 보이게 하는 인텔의 기술입니다. 물리 코어 수를 무한정 늘리기 어려운 면적·전력 제약을 보완하기 위한 설계입니다.
