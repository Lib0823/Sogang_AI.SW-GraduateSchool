# Concurrency and Locks

## 강의 내용 정리

### 강의 필기: Heap 공유와 Lock
- 하나의 프로세스 안에서 여러 스레드가 실행되면 Heap을 공유하지만, 서로 다른(부모/자식) 프로세스는 각자의 주소 공간을 가지므로 데이터를 직접 공유할 수 없어 IPC(Inter-Process Communication)를 사용해야 합니다. IPC로 공유 문제를 해결할 수는 있지만 스레드 간 공유보다 번거롭습니다.
- 하나의 프로세스에서 여러 스레드를 띄우면 Heap 메모리를 공유하므로 데이터 공유가 쉽지만, 여러 스레드가 동시에 읽고 쓰면 데이터가 꼬이는 **경합 상태(Race Condition)** 문제가 발생할 수 있습니다.
- 이 race 현상을 해결하기 위해 **Lock**을 사용해야 합니다.

### 1. 스레드(Thread)의 구조와 병렬성
- **고유 자원**: 각 스레드는 독립적인 실행을 위해 프로그램 카운터(PC), 레지스터 세트, 스택(Stack)을 개별로 가집니다.
- **공유 자원**: 같은 프로세스 내 스레드들은 코드(Code), 데이터(Data/Heap), 주소 공간(Address Space)을 공유합니다.
- **장점**: 데이터 공유가 쉽고 IPC보다 오버헤드가 적으며 병렬 처리가 가능합니다.
- **병렬 프로그래밍의 필요성**: 멀티코어 환경에서 여러 코어를 동시에 활용해 성능을 극대화하기 위함입니다. 싱글 코어에서는 실제 병렬 처리가 아니라 컨텍스트 스위칭을 통한 시분할(동시성)만 일어납니다.
- **활용 예**: 키-값(Key-Value) 쌍의 대규모 데이터를 정렬할 때, 데이터를 분할해 여러 스레드가 동시에 처리하면 실행 시간을 크게 줄일 수 있습니다.

### 2. 어드레스 스페이스와 보안
- **프로세스 독립성**: OS는 보안과 안정성을 위해 프로세스 간 주소 공간을 엄격히 분리합니다 (한 프로그램이 다른 프로그램의 메모리를 침범하는 것을 방지).
- **스레드 공유**: 같은 프로세스 내 스레드들은 주소 공간을 공유해 협업이 쉽지만, 그만큼 경쟁 상태(Race Condition)라는 위험이 함께 따라옵니다.

### 3. 임계 영역(Critical Section)과 동기화
- **경쟁 상태(Race Condition)**: 둘 이상의 스레드가 동시에 공유 데이터를 수정할 때, 실행 순서에 따라 결과가 달라지는 현상입니다.
- **원인 (Non-atomic Operation)**: `count++` 같은 단순한 코드도 CPU 레벨에서는 [메모리 읽기 → 값 증가 → 메모리 저장]의 3단계로 나뉘며, 이 사이에 컨텍스트 스위칭이 발생하면 갱신 결과가 유실되는 데이터 불일치가 생깁니다.
- **임계 영역**: 공유 자원에 접근하는 코드 영역으로, 반드시 **상호 배제(Mutual Exclusion)**가 보장되어야 합니다.

#### 락(Lock)의 종류와 동작
- **뮤텍스(Mutex)**: 락을 획득한 스레드만 임계 영역에 진입하고, 빠져나올 때 반납합니다. 다른 스레드는 락이 풀릴 때까지 대기(Blocking)합니다.
- **트라이락(Try-lock)**: 락 획득을 시도하되, 이미 다른 스레드가 점유 중이면 대기하지 않고 즉시 '실패'를 반환합니다 — 데드락을 피하거나 대기 중 다른 작업을 수행하는 데 활용할 수 있습니다.
- **파인 그레인 락(Fine-grained Lock)**: 데이터 전체에 하나의 큰 락을 거는 대신, 데이터를 여러 부분으로 나누어 각각 별도의 락을 거는 방식입니다. 병렬성은 높아지지만 구현 복잡도와 데드락 위험이 함께 커집니다.

### 4. 스레드 프로그래밍 시 주의사항 (스택과 라이프타임)
- 함수 내에서 선언된 지역 변수는 그 함수의 스택 프레임에 할당됩니다.
- **위험 요소**: 어떤 함수의 지역 변수(스택 변수) 주소를 새로 생성한 스레드에 넘겼는데, 그 함수가 먼저 리턴되어 스택 프레임이 사라지면, 해당 스레드는 이미 무효화된 메모리 주소(Dangling Pointer)를 참조하게 되어 정의되지 않은 동작이 발생할 수 있습니다.
- **해결책**: 스레드 간에 주고받는 데이터는 변수의 라이프타임(Life-time)을 고려해 힙(Heap) 영역에 할당하거나, 원본 데이터가 살아있는 동안 스레드가 안전하게 접근하도록 동기화를 철저히 해야 합니다.
