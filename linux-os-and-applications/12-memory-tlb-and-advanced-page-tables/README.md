## 강의 내용 정리

### 1. 초기 메모리 할당의 한계와 페이징의 도입
#### 1.1 초기 연속 할당과 외부 단편화
- 프로세스를 물리 메모리의 연속적인 공간에 통째로 적재하는 방식은, 프로세스의 실행·종료가 반복되면서 어느 프로세스도 들어갈 수 없는 자투리 빈 공간(외부 단편화)이 늘어나 메모리 효율이 크게 떨어집니다.

#### 1.2 페이징(Paging) 기술의 도입
- **개념**: 메모리를 논리적 단위가 아니라 고정된 크기(전형적으로 4KB)의 페이지(Page) 단위로 잘라 할당합니다.
- **주소 변환**: 가상 페이지 번호(Virtual Page Number)를 페이지 테이블을 통해 물리 프레임 번호(Physical Frame Number)로 바꾸고, 하위 오프셋(Offset)은 그대로 유지합니다.
- **페이지 크기 트레이드오프**: 페이지 크기를 키우면 페이지 테이블 전체 크기는 작아지지만, 페이지 안에서 실제로 쓰이지 않는 공간이 늘어나는 **내부 단편화(Internal Fragmentation)**가 커질 수 있습니다.

### 2. 페이지 테이블 자료 구조의 한계와 극복 (속도·공간 문제)
#### 2.1 메인 메모리(DRAM) 적재와 속도 저하 문제
- 페이지 테이블은 프로세스의 가상 주소 공간 전체를 표현해야 해 크기가 매우 크므로, MMU 내부가 아닌 메인 메모리(DRAM)에 둡니다. 그 결과 CPU는 명령어를 실행할 때마다 (1) 페이지 테이블 접근, (2) 실제 데이터 접근이라는 **두 번의 메모리 참조(Double Reference)**를 해야 해 속도가 저하됩니다.

#### 2.2 TLB(Translation Lookaside Buffer) 도입을 통한 속도 해결
- MMU 내부에 최근 사용한 주소 변환 결과를 캐싱하는 고속 하드웨어 캐시인 **TLB**를 둡니다.
- 프로그램의 메모리 접근은 대체로 시간적/공간적 지역성(Locality)을 가지므로, 한 번 접근한 페이지 테이블 엔트리는 TLB에 캐싱되어 이후 같은 페이지에 접근할 때 메인 메모리 참조 없이 즉시 변환할 수 있습니다.

#### 2.3 다단계 페이징 (Multi-level Paging)을 통한 공간 해결
- 거대한 페이지 테이블을 다시 페이지 크기 단위로 나눈 뒤, 그 위에 상위 색인 역할을 하는 **페이지 디렉터리(Page Directory)**를 두는 계층 구조입니다.
- 사용하지 않는 가상 메모리 영역에 대해서는 하위 페이지 테이블을 아예 만들지 않아도 되므로, 페이지 테이블 전체가 차지하는 메모리 공간을 크게 절약할 수 있습니다.
- 계층이 늘어나는 만큼 주소 변환 시 필요한 메모리 참조 횟수도 늘어나지만(예: 4단계 페이징이면 이론상 최대 4~5회), TLB 적중률이 충분히 높으면 실제 체감 성능 저하는 크지 않습니다.

### 3. 페이지 테이블 엔트리(PTE)와 OS 커널의 역할
페이지 테이블은 유저 프로세스가 직접 접근·수정할 수 없으며, **OS 커널 모드**에서 생성·관리하는 프로세스별 자료구조입니다.

| 비트 | 역할 |
|------|------|
| Present (P) | 해당 가상 페이지가 물리 메모리에 실제로 상주하는지(1), 디스크(Swap 영역)로 내려가 있는지(0) 표시 |
| Read/Write | 해당 메모리 영역의 읽기/쓰기 권한을 제어해 허용되지 않은 메모리 접근을 방지 |
| Dirty | 페이지가 메모리에 올라온 후 내용이 수정되었는지 표시 — 스왑 아웃 시 디스크에 다시 써야 하는지 판단하는 근거 |
| Accessed | 일정 시간 동안 해당 페이지에 접근이 있었는지 기록 — 메모리가 부족할 때 어떤 페이지를 내보낼지(스왑 정책) 결정하는 데 활용 |

### 4. 문맥 전환(Context Switch) 오버헤드와 멀티스레딩 최적화
- **프로세스 전환**: 프로세스마다 독립적인 페이지 테이블을 사용하므로, 프로세스 간 문맥 전환이 일어날 때 이전 프로세스의 주소 변환 정보가 TLB에 남아있으면 잘못된 주소로 해석될 위험이 있습니다. 따라서 프로세스가 바뀔 때마다 **TLB를 비워야(Flush)** 하며, 이는 무시할 수 없는 오버헤드로 작용합니다.
- **멀티스레드의 이점**: 같은 프로세스 내 스레드들은 가상 주소 공간과 페이지 테이블을 그대로 공유하므로, 스레드 간 전환 시에는 TLB를 비울 필요가 없어 컨텍스트 스위칭 비용이 훨씬 낮습니다.
- **한계**: 스레드는 메모리를 공유하는 만큼 개발자가 동기화 이슈(Lock, 데이터 경쟁)를 직접 관리해야 하며, 스레드 하나의 크래시가 프로세스 전체의 종료로 이어질 수 있다는 위험도 함께 따라옵니다.

### 5. 결론 및 향후 과제
1. 세그멘테이션과 초기 페이징의 속도 한계를 극복하기 위한 하드웨어 구조(MMU 레지스터 세트, TLB 용량 확대 등) 개선 방향 검토.
2. 다단계 페이징에서 늘어난 메모리 참조 오버헤드를 TLB와 연계해 최적화하는 커널 메커니즘의 이해 심화.
3. AI 워크로드의 메모리 접근 패턴을 분석해 하드웨어(MMU/DRAM)와 소프트웨어(커널) 계층의 병목을 파악하는 후속 연구.
