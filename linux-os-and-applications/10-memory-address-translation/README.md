## 강의 내용 정리

### 1. 현대 컴퓨팅 환경에서의 CPU와 GPU
최근 AI 서비스가 단일 거대 모델 위주에서 멀티 에이전트(Multi-agent) 구조로 변화함에 따라 CPU의 역할이 다시 주목받고 있습니다.
- **CPU의 역할 변화**: 실제 연산은 GPU가 주도하더라도, 데이터를 GPU로 전달하고 전체 워크플로우를 관리하는 것은 여전히 CPU의 몫입니다. 여러 에이전트가 협력하는 추론 서버 구조가 늘어나며 CPU의 오케스트레이션(작업 조율) 성능이 더욱 중요해지고 있습니다.
- **실행 흐름(Execution Flow)**: CPU 관점에서 스레드(Thread)는 하나의 실행 흐름입니다. 프로그램이 정적인 인스트럭션의 시퀀스라면, 스레드는 이를 실제로 실행하는 동적인 흐름에 해당합니다.

### 2. 멀티 스레딩과 동시성 제어
#### 메모리 공유 구조
- **스택(Stack)**: 각 스레드마다 독립적으로 할당됩니다. 함수 호출 시 파라미터와 로컬 변수를 관리합니다.
- **힙(Heap) & 데이터 영역**: 프로세스 내 모든 스레드가 공유합니다. 데이터 공유는 쉽지만 동기화 문제가 뒤따릅니다.

#### 원자성(Atomicity) 문제
- `balance = balance + 1` 같은 단순한 코드도 CPU 레벨에서는 세 단계(Load → Add → Store)의 명령어로 나뉩니다.
- **문제점**: 여러 스레드가 동시에 접근하면 이 명령어들 사이에 컨텍스트 스위치가 끼어들어, 최종 결과가 예상보다 작게 나오는 **데이터 레이스(Data Race)**가 발생할 수 있습니다.
- **해결책**: 원자성을 보장하기 위해 임계 구역(Critical Section)을 설정하고 락(Lock)을 사용해야 합니다.

### 3. 동기화 메커니즘: 락(Lock)과 인터럽트
#### 락 설계의 원칙
1. **상호 배제(Mutual Exclusion)**: 한 번에 하나의 스레드만 락을 획득해야 합니다.
2. **공정성(Fairness)**: 특정 스레드가 무한정 대기하지 않도록 대기 순서를 합리적으로 보장해야 합니다.

#### 하드웨어 지원의 필요성
- **인터럽트 비활성화(Interrupt Disable)**: 인터럽트를 잠시 막아 원자성을 확보하는 방법이지만, 시스템 전체에 영향을 주는 오버헤드가 크고 멀티코어 환경에서는 다른 코어의 접근까지 막지 못한다는 한계가 있습니다.
- **원자적 명령어**: 소프트웨어만으로는 완벽한 락을 구현하기 어려우므로, CPU가 제공하는 Test-and-Set과 같은 하드웨어 원자적 명령어를 활용해야 합니다.
- **스핀락(Spinlock)**: 락을 얻을 때까지 CPU를 점유한 채 반복 확인(busy-wait)하며 대기하는 방식입니다.
  - 싱글 코어: 스피닝하는 스레드가 CPU를 계속 점유해 다른 작업을 막으므로 오히려 성능이 저하될 수 있습니다.
  - 멀티 코어: 락을 곧 놓아줄 것으로 예상되는 짧은 대기 구간에서는, 컨텍스트 스위치 비용보다 잠깐 스피닝하는 편이 더 효율적일 수 있습니다.

### 4. 메모리 가상화와 멀티 프로그래밍
메모리 가상화는 물리적 메모리를 추상화하여 사용자 프로세스에게 독립된 주소 공간을 제공하는 기술입니다.

**가상화의 목적**
1. **보호(Protection)**: 프로세스가 OS 영역이나 다른 프로세스의 메모리를 침범하지 못하게 합니다.
2. **투명성(Transparency)**: 프로세스가 마치 메모리 전체를 독점하고 있는 것처럼 동작하게 합니다.
3. **효율성(Efficiency)**: 물리적 메모리를 낭비 없이 여러 프로세스가 나누어 사용하게 합니다.

**주소 재배치(Relocation) 방법**

| 구분 | 설명 | 장단점 |
|------|------|--------|
| 타임 셰어링 | 프로세스 전체를 디스크로 내렸다가 올림 (Swapping) | 매우 느리고 비효율적 |
| 공간 셰어링 | 메모리를 분할하여 여러 프로세스를 동시에 상주시킴 | 효율적이지만 주소 충돌 관리 필요 |
| 정적 재배치 (Static) | 로드 타임에 소프트웨어적으로 주소를 수정 | 실행 중 위치 변경 불가, 원시적 방식 |
| 동적 재배치 (Dynamic) | CPU의 Base/Bound 레지스터를 이용해 런타임에 주소 변환 | 유연하고 안전하지만 하드웨어 지원 필수 |

### 5. 메모리 액세스의 실제 (Register & Stack)
CPU가 데이터를 처리할 때 발생하는 일반적인 메모리 참조 과정:
1. **Instruction Fetch**: 메모리 주소에서 명령어를 가져옴.
2. **Decode**: 명령어를 해석 (예: 특정 메모리 오프셋의 데이터를 읽으라는 지시).
3. **Address Calculation**: RBP(Base Pointer) + Offset 등으로 실제 유효 주소를 계산.
4. **Execute**: ALU를 통해 연산 수행.
5. **Memory Access**: 연산 결과를 메모리에 저장(Store)하거나 값을 읽음(Load).
