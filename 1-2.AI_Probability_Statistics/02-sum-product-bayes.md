# 인공지능 확률통계 — 2강 정리
## Sum Rule, Product Rule, Bayes' Theorem, Graphical Model

> 이번 강의 한 줄 요약
> **"확률 계산은 결국 세 가지다 — 더하기(Sum), 곱하기(Product), 그리고 그 둘을 조합한 뒤집기(Bayes)."**

---

## 0. 강의의 뼈대

교수님이 칠판 맨 위에 적은 세 줄이 이 강의 전체다.

| 필기 | 정식 명칭 | 하는 일 |
|---|---|---|
| 더하기 | **Sum Rule** (합의 법칙) | 관심 없는 변수를 **없앤다** |
| 곱하기 | **Product Rule** (곱의 법칙) = Chain Rule | 복잡한 확률을 **쪼갠다** |
| — | **Bayes' Theorem** (베이즈 정리) | 조건을 **뒤집는다** |

이 세 개만 자유롭게 쓸 수 있으면 이 과목의 계산 문제는 거의 다 풀린다.

---

## 1. Joint Probability Table — 모든 것의 출발점

강의에서 쓴 표(필기 그대로):

| | x₁ | x₂ | x₃ | x₄ | x₅ |
|---|---|---|---|---|---|
| **y₃** | 0.01 | 0.02 | 0.03 | 0.1 | 0.1 |
| **y₂** | 0.05 | 0.1 | 0.05 | 0.07 | 0.2 |
| **y₁** | 0.1 | 0.05 | 0.03 | 0.05 | 0.04 |

각 칸 하나가 `P(X=xᵢ, Y=yⱼ)` — **X와 Y가 동시에 그 값일 확률**이다.
표 전체를 다 더하면 1이 된다. (확률의 기본 성질)

### 여기서 뽑아낼 수 있는 세 종류의 확률

| 종류 | 영어 | 표에서 읽는 법 |
|---|---|---|
| 결합확률 | **Joint probability** | 칸 하나 그대로 |
| 주변확률 | **Marginal probability** | 한 줄(행 또는 열)을 다 더함 |
| 조건부확률 | **Conditional probability** | 칸 ÷ 그 줄의 합 |

## 2. Sum Rule (합의 법칙) = Marginalization

### 정의

```
P(X = x₃) = Σ P(X = x₃, Y = yⱼ)
             j

P(X) = Σ P(X, Y)     ← Y를 "지워버린다"
        Y
```

### 강의 계산 그대로

```
P(X = x₃) = P(x₃, y₁) + P(x₃, y₂) + P(x₃, y₃)
          = 0.03 + 0.05 + 0.03
          = 0.11
```

### 직관

> 표에서 **세로 한 줄을 손으로 훑어서 다 더하는 것**.
> Y가 뭐였는지는 관심 없다 → Y를 모든 경우에 대해 더해서 **없애버린다**.

이 "더해서 없애기"를 **Marginalization(주변화)** 라고 부른다.
`P(X)`처럼 하나만 남은 확률을 **Marginal probability(주변확률)** 라고 하는 이유는,
옛날에 표를 손으로 그릴 때 행/열의 합을 **표 가장자리(margin)** 에 적었기 때문이다.

> ⚠️ **중요:** Sum Rule은 "확률을 더한다"가 아니라 **"변수를 하나 제거한다"** 로 이해해야 한다.
> 문제에서 "이 변수는 몰라도 되는데?" 싶으면 그게 Sum Rule 쓸 타이밍이다.

---

## 3. Product Rule (곱의 법칙) = Chain Rule

### 정의

```
P(X, Y) = P(X) · P(Y | X)
        = P(Y) · P(X | Y)      ← 순서를 바꿔도 성립
```

두 줄이 **같은 값**이라는 게 핵심이다. 이 두 줄이 곧바로 Bayes 정리를 만든다.

### 강의 계산 그대로

```
P(Y = y₂ | X = x₃) = P(X = x₃, Y = y₂) / P(X = x₃)
                    = 0.05 / 0.11
                    ≈ 0.4545
```

- 분자 `0.05` : 표에서 (x₃, y₂) 칸
- 분모 `0.11` : 방금 Sum Rule로 구한 `P(X = x₃)`

### 직관

> **조건부확률 = 그 줄 안에서의 비율.**
> "X = x₃인 세상"으로 이미 좁혀졌으니, x₃ 열(합 0.11)을 새로운 100%로 삼고
> 그 안에서 y₂가 차지하는 비중(0.05)을 본다.

### 일반화 — Chain Rule

변수가 N개여도 똑같이 쪼갤 수 있다.

```
P(X₀, X₁, X₂, …, X_N)
  = P(X₀) · P(X₁|X₀) · P(X₂|X₀,X₁) · … · P(X_N | X₀,…,X_{N-1})
```

앞에서부터 하나씩 조건에 넣으며 사슬(chain)처럼 이어붙인다.

## 4. Graphical Model (그래프 모델)

Product Rule을 **그림으로** 나타낸 것.

### 4-1. 가장 단순한 형태

```
Ⓧ ──→ Ⓨ        ⇔    P(X, Y) = P(X) P(Y|X)
```

화살표 `X → Y`의 의미:
> **"Y의 확률이 X 값에 따라 달라진다"** (X가 Y의 원인 / 부모 노드)

### 4-2. 3개 변수 — 체인 구조

```
Ⓧ ──→ Ⓨ ──→ Ⓩ
```

```
P(X, Y, Z) = P(X) · P(Y, Z | X)
           = P(X) · P(Y|X) · P(Z|Y, X)
                                    ↑
                        체인 구조에서는 이 X가 떨어져 나간다
                              → P(Z|Y)
```

`Z`는 `Y`만 알면 되고 `X`는 더 볼 필요가 없다 → 이게 **Markov 성질**이다.

### 4-3. Markov Chain

```
Ⓧ₀ → Ⓧ₁ → Ⓧ₂ → Ⓧ₃ → … → Ⓧ_N
```

```
일반 Chain Rule:
P(X₀:N) = P(X₀) P(X₁|X₀) P(X₂|X₀,X₁) … P(X_N|X₀,…,X_{N-1})

Markov 가정을 넣으면:
P(X₀:N) = P(X₀) P(X₁|X₀) P(X₂|X₁) … P(X_N|X_{N-1})
```

> **한 줄 정의:** 미래는 **현재**에만 의존하고, 과거는 잊어도 된다.
> (현재 상태가 과거 정보를 이미 다 요약하고 있기 때문)

계산량이 폭발적으로 줄어드는 게 이 가정의 실익이다.

### 4-4. 두 부모 → 한 자식 (V 구조)

```
Ⓧ     Ⓨ
  ↘   ↙
    Ⓩ
```

```
P(X, Y, Z) = P(X) · P(Y) · P(Z | X, Y)
              └── X와 Y는 서로 독립 ──┘
```

X와 Y 사이에는 화살표가 없다 → **처음엔 서로 독립**이다.
(단, Z를 관측하고 나면 X와 Y가 서로 얽히게 된다 — 나중 강의에서 다룸)

> 💡 **그래프 모델의 실용적 가치:**
> 그림만 보면 곱셈 식을 바로 쓸 수 있고, 반대로 곱셈 식을 보면 그림을 그릴 수 있다.

## 5. Bayes' Theorem (베이즈 정리)

### 5-1. 유도 — Product Rule 두 줄에서 바로 나온다

```
P(X=x₃, Y=y₂) = P(X=x₃) · P(Y=y₂ | X=x₃)      … ①
P(X=x₃, Y=y₂) = P(Y=y₂) · P(X=x₃ | Y=y₂)      … ②

①과 ②는 같은 값이므로, ②를 P(Y=y₂)로 나누면:
```

```
                 P(X=x₃) · P(Y=y₂ | X=x₃)
P(X=x₃ | Y=y₂) = ─────────────────────────
                        P(Y=y₂)
```

### 5-2. 각 항의 이름과 의미 ⭐ 시험 필수

| 위치 | 기호 | 영어 | 한국어 | 의미 |
|---|---|---|---|---|
| 좌변 | `P(X\|Y)` | **Posterior** | 사후확률 | 데이터를 **본 뒤** 갱신된 믿음 |
| 분자 앞 | `P(X)` | **Prior** | 사전확률 | 데이터 **보기 전**의 믿음 |
| 분자 뒤 | `P(Y\|X)` | **Likelihood** | 우도(가능도) | X가 참일 때 이 데이터가 나올 그럴듯함 |
| 분모 | `P(Y)` | **Evidence** | 증거 | 데이터가 나올 전체 확률 (**정규화 상수**) |

여기서 조건에 들어가는 `Y`가 곧 우리가 실제로 **측정한 데이터(Data)** 다.

```
                Prior × Likelihood
Posterior = ───────────────────────
                    Evidence
```

### 5-3. Evidence 계산 — 여기서 Sum Rule이 다시 등장

분모 `P(Y=y₂)`는 직접 주어지지 않는 경우가 많다. 이때 Sum Rule로 만든다.

```
                            P(X=x₃) P(Y=y₂|X=x₃)
P(X=x₃ | Y=y₂) = ─────────────────────────────────────
                    Σ  P(X=xᵢ) P(Y=y₂ | X=xᵢ)
                    i
```

> **분모 = 분자를 모든 X에 대해 다 더한 것.**
> 그래서 분모를 **Normalization constant(정규화 상수)**, 줄여서 `Z` 라고 쓴다.

### 5-4. 실전 계산 순서 (강의에서 강조된 방법)

```
1단계  분자만 전부 계산한다      →  P(X) × P(data|X)   (각 X마다)
2단계  다 더해서 Z를 구한다       →  Z = Σ 분자
3단계  각각을 Z로 나눈다          →  Posterior
```

이 과정을 기호로 이렇게 쓴다:

```
P(X | data) ∝ P(X) · P(data | X)
              └── ∝ : "비례한다" (proportional to)
```

> ⚠️ 교수님 강조 포인트
> `∝` 로 놔두면 **확률분포가 아니다**. 다 더해도 1이 안 된다.
> **확률분포 자체를 원하면 Z로 반드시 나눠야 한다.**

## 6. 예제 1 — 주사위 문제 (Dice Problem)

### 문제

> 통 안에 **6면체(D6), 8면체(D8), 12면체(D12)** 주사위가 하나씩 들어 있다.
> 눈 감고 하나를 꺼내 굴렸더니 **1**이 나왔다.
> 내가 꺼낸 주사위가 각각일 확률은?

### 문제 세팅 — "무엇이 X이고 무엇이 데이터인가"

| 기호 | 의미 |
|---|---|
| `X` | 어떤 주사위를 뽑았는가 (**숨겨진 원인**, latent) |
| `data (Y=1)` | 눈 1이 나왔다 (**관측된 결과**) |
| 구하는 것 | `P(X | Y=1)` ← **결과로부터 원인을 역추적** |

### 계산 표

| X | Prior `P(X)` | Likelihood `P(Y=1\|X)` | 분자 `P(X)P(Y=1\|X)` | Posterior `P(X\|Y=1)` |
|---|---|---|---|---|
| D6 | 1/3 | 1/6 | 1/18 | **4/9 ≈ 0.444** |
| D8 | 1/3 | 1/8 | 1/24 | **3/9 = 1/3 ≈ 0.333** |
| D12 | 1/3 | 1/12 | 1/36 | **2/9 ≈ 0.222** |
| | | | **Z = 1/8** | 합 = 1 ✅ |

### 검산

```
Z = 1/18 + 1/24 + 1/36
  = 4/72 + 3/72 + 2/72
  = 9/72 = 1/8

P(D6 | Y=1) = (1/18) / (1/8) = 8/18 = 4/9
```

### 💡 계산 요령 (교수님 팁)

Prior가 전부 1/3로 같으므로 **밖으로 빼면 약분되어 사라진다**:

```
                    1/6                1/6
P(D6|Y=1) = ───────────────────  =  ────── = 4/9
             1/6 + 1/8 + 1/12       3/8
```

> 시험에서 공통 인수는 굳이 안 적어도 된다. 다만 **정리는 깔끔하게** 할 것.

### 직관

> 면이 적은 주사위일수록 **1이 나오기 쉽다**.
> 그래서 1을 봤다는 사실이 "D6였을 가능성"을 **끌어올린다**.
> 처음엔 1/3, 1/3, 1/3 이던 믿음이 → 4/9, 3/9, 2/9 로 **기울어졌다**.
> 이것이 **"데이터로 확률을 업데이트한다"** 의 정확한 의미다.

## 7. 예제 2 — 몬티 홀 문제 (Monty Hall Problem)

### 문제

> 문이 **3개**, 그중 하나 뒤에 자동차, 나머지는 꽝.
> 내가 **1번 문**을 선택했다.
> 진행자(쇼호스트)가 **3번 문**을 열어 꽝임을 보여줬다.
> **2번으로 바꿔야 하는가?**

### 흔한 오답과 그 이유

> ❌ "문이 2개 남았으니 각각 1/2이다."
> → **틀렸다.** 진행자는 **아무 문이나 연 게 아니다.** 정답을 알고, 꽝인 문만 골라 열었다.
> 이 "진행자의 규칙"이 정보를 담고 있기 때문에 확률이 대칭이 아니다.

### 문제 세팅 — 강의에서 가장 강조한 부분

> **"문제는 X를 어떻게 적느냐다."**

| 기호 | 의미 |
|---|---|
| `X` | 자동차가 실제로 있는 문 (`D₁`, `D₂`, `D₃`) — **숨겨진 원인** |
| `data` | 진행자가 **3번 문을 열었다** — **관측된 결과** |

### 핵심 — Likelihood `P(data | X)` 를 정확히 따지기

내가 **1번**을 골랐다는 전제하에, 진행자가 **3번**을 열 확률:

| 자동차 위치 | 진행자가 열 수 있는 문 | `P(3번을 연다 \| X)` |
|---|---|---|
| **D₁** (내가 고른 문) | 2번, 3번 둘 다 가능 → 랜덤 선택 | **1/2** |
| **D₂** | 1번은 내가 골랐고 2번은 자동차 → **3번밖에 없음** | **1** |
| **D₃** | 3번이 자동차 → **절대 못 연다** | **0** |

### 계산 표

| X | Prior `P(X)` | Likelihood `P(data\|X)` | 분자 | Posterior `P(X\|data)` |
|---|---|---|---|---|
| Car D₁ | 1/3 | 1/2 | 1/6 | **1/3** |
| Car D₂ | 1/3 | 1 | 1/3 | **2/3** ⭐ |
| Car D₃ | 1/3 | 0 | 0 | **0** |
| | | | **Z = 1/2** | 합 = 1 ✅ |

### 결론

```
바꾸지 않는다 → 1/3
바꾼다        → 2/3     ✅ 무조건 바꿔야 한다
```

### 직관

> 내가 처음 고른 문이 정답일 확률은 **처음부터 끝까지 1/3로 변하지 않는다.**
> 진행자는 내 문에 대해 아무 정보도 주지 않았기 때문이다.
> 대신 **나머지 2/3가 열리지 않은 2번 문 하나로 전부 몰린다.**

### 💡 교수님이 강조한 메시지

> **"감정은 버리고, 순수한 차가운 이성으로 —
> X에 해당하는 게 무엇이고, 각각이 선택될 확률은 얼마인지"**

직관이 배신하는 문제일수록, **X와 data를 정확히 정의하고 표를 그리면** 기계적으로 풀린다.

## 8. 예제 3 — 쿠키(그릇) 문제 (Cookie / Bowl Problem)

### 문제

> **그릇 1 (B₁)**: 바닐라 30개, 초코 10개 (총 40개)
> **그릇 2 (B₂)**: 바닐라 20개, 초코 20개 (총 40개)
>
> 눈 감고 그릇 하나를 골라 쿠키 하나를 꺼냈더니 **바닐라**였다.
> **그릇 1**에서 꺼냈을 확률은?

### 문제 세팅

| 기호 | 의미 |
|---|---|
| `X` | 어느 그릇에서 꺼냈는가 (`B₁`, `B₂`) — **숨겨진 원인** |
| `data (Y=Vanilla)` | 바닐라가 나왔다 — **관측된 결과** |

### 계산 표

| X | Prior `P(X)` | Likelihood `P(Y=Van\|X)` | 분자 | Posterior `P(X\|Y=Van)` |
|---|---|---|---|---|
| B₁ | 1/2 | 30/40 = 3/4 | 3/8 | **3/5 = 0.6** |
| B₂ | 1/2 | 20/40 = 1/2 | 2/8 | **2/5 = 0.4** |
| | | | **Z = 5/8** | 합 = 1 ✅ |

```
P(X | Y=data) = P(X) · P(Y=data | X) / Z
                                        ↑ normalization constant
```

### 직관

> 처음엔 **50 : 50** 이었다.
> 바닐라를 하나 봤더니 → **60 : 40** 으로 기울었다.
> 그릇 1이 바닐라 비율이 더 높으므로, 바닐라를 봤다는 사실이 "그릇 1이었다"는 쪽을 지지한다.
> **믿음이 완전히 뒤집힌 게 아니라, 데이터가 준 만큼만 기울었다.** 이게 베이즈적 사고다.

### 🔁 이상적 가정 (강의 언급)

> 쿠키를 꺼내면 **자동으로 다시 채워진다**고 가정한다.
> 이렇게 해야 매 시행의 확률이 변하지 않고, 계산이 단순해진다.
> (안 채워지면 두 번째 뽑기의 Likelihood가 달라져서 훨씬 복잡해진다.)

## 9. Random Variable (확률변수) 복습

### 정의

> **Sample space(표본공간)의 각 결과(outcome)에 숫자를 대응시키는 함수.**

```
동전 던지기
Event(사건) = { 앞, 뒤 }

X(앞) = 1
X(뒤) = 2      ← 숫자는 우리가 마음대로 assign 해도 된다
```

### 왜 숫자로 바꾸는가

| 이유 | 설명 |
|---|---|
| 계산 가능 | "앞면"은 못 더하지만 `1`은 더할 수 있다 |
| 배열 연산 | Categorical(범주형)은 **discrete**이므로 array operation으로 처리 |
| 코드 구현 | `[0.5, 0.5]` 같은 벡터로 다루면 프로그램에 그대로 들어간다 |

> 💡 값 자체(1이냐 2냐)는 중요하지 않다. **구분만 되면 된다.**

## 10. 문제 풀이 표준 절차 ⭐

어떤 베이즈 문제든 이 순서를 그대로 따르면 된다.

```
① X를 정의한다        →  "숨겨진 원인은 무엇인가?"  (내가 알고 싶은 것)
② data를 정의한다     →  "내가 실제로 관측한 것은 무엇인가?"
③ Prior P(X)          →  데이터 보기 전 각 X의 확률
④ Likelihood P(data|X)→  각 X가 참일 때 이 데이터가 나올 확률   ← 여기가 제일 어렵다
⑤ 분자 계산            →  P(X) × P(data|X)   (각 X마다)
⑥ Z = Σ 분자
⑦ Posterior = 분자 / Z
⑧ 검산                →  다 더하면 1인가?
```

> **제일 많이 틀리는 곳은 ④ Likelihood다.**
> 몬티 홀에서 `P(3번을 연다 | D₁) = 1/2` 을 놓치면 답이 1/2로 나온다.
> **"이 상황에서 진행자/자연이 어떻게 행동하는가"** 를 끝까지 따져야 한다.

## 12. 자주 헷갈리는 포인트 ⚠️

| 헷갈림 | 정리 |
|---|---|
| `P(X,Y)` vs `P(X\|Y)` | 콤마 = **동시에**, 세로줄 = **조건** |
| `P(Y\|X)` vs `P(X\|Y)` | **완전히 다른 값**. 순서 바꾸려면 Bayes 필요 |
| Likelihood는 확률분포? | ❌ `P(data\|X)`를 **X에 대해** 더해도 1이 아니다 |
| `∝` 로 끝내도 되나? | ❌ 확률분포를 원하면 반드시 Z로 나눠라 |
| Prior가 다 같으면? | 약분되어 사라짐 → Likelihood 비율이 곧 Posterior 비율 |
| Evidence는 어떻게 구하나 | 분자를 **모든 X에 대해 더한 것** (Sum Rule) |
| 몬티 홀에서 왜 1/2이 아닌가 | 진행자가 **정답을 알고** 꽝만 골라 열기 때문 |

## 13. 다음 강의로 이어지는 흐름

이번 강의에서 다룬 것은 전부 **Discrete(이산)** 확률이다.

```
[2강] Discrete 확률
   Sum Rule / Product Rule / Bayes / Graphical Model
        ↓
[다음] Continuous 확률
   Σ  →  ∫  (합 → 적분)
   확률 → 확률밀도(PDF)
        ↓
[이후] Gaussian, Parameter Estimation (MLE / MAP)
```

> 규칙 자체는 **똑같다.** `Σ`가 `∫`로 바뀔 뿐이다.
> 그래서 지금 Sum/Product/Bayes를 확실히 잡아두면 뒤가 훨씬 편하다.
